# Polisnab module drafting

Точка входа для черчения 2D-планов модулей Полиснаба через MCP-сервер
`autocad-mcp` (инструмент `mcp__autocad-mcp__polisnab`, бэкенд file_ipc → живой
AutoCAD 2027). Детали живут в двух файлах — этот SKILL их не дублирует:

- **`CLAUDE.md`** (корень репо) — грабли и правила (FILEDIA, сериализация
  координат, forward slashes, `ok:true`≠успех, правила расстановки мебели,
  пристенные элементы, `wall_side` offset). **Перечитывай перед нетривиальной
  ручной сборкой.**
- **`PROJECT-BRIEF-autocad-mcp-polisnab.md`** — полный план, стандарт слоёв,
  dimstyle, реальные размеры компонентов, статус фаз.

## 0. Проверка окружения (ДО первого черчения)

Не начинать, пока не подтверждено:

1. **MCP подключён.** Инструменты `mcp__autocad-mcp__*` доступны. Если нет —
   `/mcp reconnect`. Реконект обязателен после **любой** правки Python (даже
   одной константы).
2. **AutoCAD виден и развёрнут** на весь экран. Свёрнутое/перекрытое окно →
   `get_screenshot` вернёт чёрный кадр. Если кадр чёрный при видимом окне —
   попросить пользователя выполнить `REGENALL` в командной строке AutoCAD.
3. **Диспетчер перезагружен для ЭТОГО чертежа.** LISP-диспетчер
   (`lisp-code/mcp_dispatch.lsp`) живёт в namespace конкретного документа.
   Открыли новый чертёж → диспетчер потерян → `APPLOAD` или
   `(load ".../mcp_dispatch.lsp")` в этом документе. Симптом потери: команды
   молча не срабатывают.

Быстрая проверка состояния без скриншота: `drawing info` / `get_variables`.
Скриншоты большие и жгут контекст — снимать, только когда действительно нужно
*увидеть* геометрию (см. CLAUDE.md § Screenshots).

## 1. Что использовать: шаблон или ручная сборка

Два готовых генератора Phase 4 (`operation` инструмента `polisnab`) собирают
всю сцену — стандарты + оболочку + проёмы + мебель — одним вызовом на **пустом**
чертеже. Всегда предпочитай их ручной сборке, когда запрос ложится на шаблон.

### `generate_dormitory_room` — общежитие / вахтовый модуль
Референс `reference-4bed-room-layout.png`. Дверь (юг) + окно (восток) + ряд
локеров (запад) + пара(ы) односпальных кроватей у восточной стены, разделённых
зазором (не перегородкой).

`data`: `length_mm` (=6000), `width_mm` (=2400), `series` (="arctic"),
`bed_pairs` (=1).
- **Только `bed_pairs=1` подтверждён вживую (скриншотом).** `bed_pairs>1`
  раскладывается по аналогии, возвращается `verified=false` + warning — не
  считать финалом без визуальной проверки.

### `generate_studio_module` — студия-модуль
Референс `reference-studio-module-layout.png`, сжатый в 6000x2400. Дверь + окно
+ двуспальная кровать + тумба + стол + стул + шкаф + изолированный санузел (душ +
унитаз + раковина за реальной дверью) + конвектор + щиток.

`data`: `length_mm` (=6000), `width_mm` (=2400), `series` (="arctic").
- **Никогда не помечен verified live** — эта плотная комбинация всегда
  возвращается `verified=false`. Подтверждать скриншотом перед сдачей.

`series` определяет толщину стены: `arctic` = 150 мм, `standard` = 75 мм.
Оба генератора возвращают per-step ok/error, `entities`, `verified`, `warnings`.
**`verified=false` = геометрию ещё не смотрели глазами** — проверь скриншот
перед тем как доверять.

### Когда собирать из примитивов
Ручная сборка (`draw_module_outline` → `insert_interior_wall` → двери/окна →
мебель по отдельным `insert_*`), когда:
- планировка не совпадает ни с одним из двух референсов (другой набор зон,
  тамбур/гардероб, нестандартное деление);
- нужен размер вне 6000x2400 с иной раскладкой, чем просто масштабированный
  шаблон;
- пользователь диктует конкретную расстановку узел за узлом.

При ручной сборке действует весь свод правил из CLAUDE.md — особенно:
- **пристенные элементы** (конвектор/сплит/щиток/душ/тумба/шкаф) — только у
  стены, тыльной гранью к внутренней грани, центр на `depth_mm/2` от неё;
- **`rotation_deg=0` у разных генераторов = РАЗНЫЕ стены** (toilet/sink → +Y
  север; convector/split/panel/nightstand/wardrobe → −Y юг; shower — угловой
  −X/−Y). Проверять по докстрингу каждого;
- **между мебелью не ставить `insert_interior_wall`** — читается как несущая
  стена; кровати рядом разделяются **зазором**;
- **`wall_side` offset отсчитывается от ВНЕШНЕГО угла** — ряд у стены начинать
  от внутренней грани (`offset=t`), ширину ячейки ужимать под чистый пролёт
  (`W-2t`), иначе крайние ячейки тонут в торцах;
- **`erase_window` прибит к слоям стен** (`AR-WALL`/`AR-WALL-INSUL`) — мебель им
  не стереть; для мебели `entity list <layer>` → `entity erase` по хэндлам.

## 2. Ключевые стандарты (кратко — детали в PROJECT-BRIEF § 4–7)

- **Слои** (11 шт, `setup_layers`): `AR-WALL`, `AR-WALL-INSUL`, `AR-DOOR`,
  `AR-WIND`, `AR-VENT`, `AR-VESTIBULE`, `DIM`, `TEXT`, `AXIS`, `TITLE-BLOCK`,
  `HATCH-FLOOR`; мебель/сантехника → `FURN`.
- **Dimstyle** (`setup_dimstyle`): `POLISNAB-DIM`, DIMSCALE≈40, мм, целая
  точность, текст над линией.
- **Реальные размеры** (не выдумывать — см. PROJECT-BRIEF § 7): вход. дверь
  950, межкомн. 840, окна 925/1120, кровать single 900×2000 / double
  1200×2000, локер-ячейка ~600×420, душ **только 800 или 900** (не 1200).
- Стандарты (`setup_layers` + `setup_dimstyle`) применяются один раз на новом
  чертеже до детализации — генераторы Phase 4 делают это сами первым шагом.

## 3. Верификация — `ok:true` не есть успех

`drawing save` / `save_as_dxf` / `plot_pdf` эхом возвращают путь без проверки
записи. Всегда проверять артефакт на диске (или `DWGTITLED`/`DWGNAME`).
Пути — только forward slashes (`C:/...`). После генерации, помеченной
`verified=false`, — скриншот перед сдачей результата.

## 4. Мелкие декоративные значки

Глифы (дверные символы, иконки мебели) НЕ сходятся через несколько раундов
текстово-координатного описания. Если значок не тот после **2–3 попыток** —
прекратить описывать прозой; либо (а) дать агенту свободу дизайна в заданных
границах, либо (б) дать **референс-изображение** для попиксельного анализа
(Python + PIL). Зумленный кроп — это всё ещё «на глаз» (стоило 3 неверных
раковин): дампить прогоны тёмных пикселей по строкам и сверять заявленный размер
с измеренной фичой, чтобы найти реальный масштаб.

**Параметризуй то, что будут подбирать на глаз.** Величина, которую явно будут
крутить (угол створки, длина панели, размер глифа) → сразу в аргумент
генератора: тогда следующая примерка = одна вставка и ноль реконектов.
